# 知识库文档清单与准备指南

> 目标：8–10 份文档、约 170–200 个 chunk，覆盖 `kb` / `sql` / `both` / `unanswerable` 四类问答。
> 原则：法律文本保证体量与权威性，内部制度保证与 Northwind 业务库咬合。

---

## 一、为什么选「电商合规」主题

| 考量 | 结论 |
|---|---|
| 与业务库同域 | Northwind 是商品/客户/订单，退货、折扣、库存、发货时效全部对得上，`both` 路线才自然 |
| 版权安全 | 《著作权法》第五条排除法律法规，法条可自由使用 |
| 引用效果好 | 法条有「第 X 条」编号，引用可精确到条款，不是模糊的"第 3 页" |
| 中文原生 | 省掉中文问句→英文语料的跨语言检索损耗 |
| 有"未规定"情形 | 法条覆盖不到的细节正好用来做 `unanswerable` 测试题 |

## 二、需要你自行下载的（公开、合法）

从**中国政府网 / 全国人大网 / 市场监管总局官网**获取，保存为 PDF 或网页另存为 Markdown。

| # | 文档 | 大致字数 | 预计 chunk | 主要用途 |
|---|---|---|---|---|
| 1 | 《中华人民共和国电子商务法》（2019 施行） | 1.5 万 | ~35 | 平台责任、合同成立、押金退还 |
| 2 | 《中华人民共和国消费者权益保护法》（2013 修正） | 1.2 万 | ~28 | 七天无理由、三包、欺诈赔偿 |
| 3 | 《消费者权益保护法实施条例》（2024 施行） | 0.8 万 | ~18 | 无理由退货细则、赠品责任 |
| 4 | 《网络交易监督管理办法》（2021） | 1.0 万 | ~22 | 信息公示、评价管理、自动续费 |
| 5 | 《中华人民共和国价格法》 | 0.6 万 | ~14 | 明码标价、价格欺诈、促销原价 |
| 6 | 《民法典》合同编·买卖合同章（节选） | 1.0 万 | ~22 | 交付、风险转移、违约责任 |

合计约 6.1 万字、约 140 个 chunk。

**下载后必须做的三件事：**

1. **保留条款编号**——不要在清洗时删掉「第二十五条」，这是引用锚点
2. **保留章节层级**——`第三章 消费者权益保护 / 第一节 消费者的权利`，写进 `section_path`
3. **统一为 Markdown**——标题用 `#` `##` `###`，正文纯文本，表格转成 Markdown 表格

## 三、已为你生成的（模拟企业内部制度，4 份）

放在同目录下，可直接入库。这些是"虚构但合理"的内部规范，作用是让 `both` 路线有真正的跨源问题。

| 文件 | 字数 | 咬合的 Northwind 字段 |
|---|---|---|
| `01-数据字典-Northwind字段对照.md` | ~3 千 | 全部表结构 + 中文别名（**这份同时是 Text2SQL 的语义层**） |

合计约 9 千字、约 25 个 chunk。总计约 165 个 chunk，足够跑 Hit@5 评测。

## 四、文档在项目里的分工

```
kb 路线（只查文档）      → 法条 + 内部制度
sql 路线（只查数据库）   → Northwind（日期已平移到 2025 年）
both 路线（两者都要）    → 内部制度的阈值/规则 + 实际数据
unanswerable            → 法条与制度都未覆盖的问题
```

`both` 路线之所以能成立，关键在**内部制度里写了具体数值阈值**（如"折扣超过 15% 需二级审批""库存低于再订货点 1.2 倍触发预警"），而实际数据在数据库里。这样问题天然就是跨源的。

## 五、入库与切分参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| 分块大小 | 400–500 字 | 中文按字符算，不要用 token 估算器，容易偏差 |
| 重叠 | 80 字 | 保证跨块的条款不被切断 |
| 分割优先级 | `\n## ` → `\n### ` → `\n\n` → `。` | 优先在章节边界切 |
| 元数据 | `doc_name`、`section_path`、`article_no`（如"第二十五条"） | 后两个是引用溯源的关键 |

> 法条类文档建议**按"条"切分**，一条一个 chunk。虽然大小不均，但检索精度和引用效果都最好——用户问"七天无理由"，直接命中第二十五条，位置精确。

## 六、避免的坑

- ❌ 别爬知乎、公众号、CSDN——来源说不清，且可能侵权
- ❌ 别用技术文档（K8s、FastAPI）——和 Northwind 无交集，`both` 路线立不住
- ❌ 别把法条清洗成一段连续文字——丢掉条款编号等于丢掉引用锚点
- ❌ 别一次导入 50 份——chunk 太多反而稀释召回精度，150–250 个是最舒服的区间
- ✅ 一份 `unanswerable` 素材：法条没规定的事（如"公司明年的开店计划"）就能直接出题
