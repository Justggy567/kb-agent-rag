# Northwind 商城数据字典

> 文档编号：NW-DICT-001  
> 版本：v1.0  
> 适用范围：本文档为 Northwind 商城业务数据的权威定义，所有指标口径以本文档为准。  
> 说明：本文件同时作为智能问答系统的语义层依据，凡涉及数据口径的争议，一律以本字典为准。



---

## 第一章 总则

### 第一条 文档用途

本字典定义 Northwind 商城业务数据库中各表的含义、字段的中文名称与业务口径。任何报表、看板、分析结论中出现的指标名称，均应与本字典保持一致。

### 第二条 命名规则

数据库字段使用英文，业务沟通使用中文。本字典中的"中文名称"字段即为对外统一称谓，"常用别名"用于兼容历史叫法与口语表达。

### 第三条 数据周期

系统内订单数据统计区间为 2025 年 1 月 1 日至 2026 年 11 月 30 日（约 23 个自然月）。若问询的时间范围超出该区间，应答复"无该时段数据"。

> 说明：该区间由 `scripts/load_northwind.py` 的日期平移量决定（Northwind 原始数据整体平移 28 年 6 个月）。若你修改了平移量，本条的日期必须同步修改，否则会出现"文档说没有数据、库里却查得到"的矛盾。

---

## 第二章 客户表（Customers）

### 第四条 表用途

记录与本商城发生交易的客户主体信息。一个客户可对应多张订单。

### 第五条 主要字段

| 中文名称  | 字段名          | 说明         |
| ----- | ------------ | ---------- |
| 客户编号  | CustomerID   | 主键，5 位大写字母 |
| 公司名称  | CompanyName  | 客户企业全称     |
| 联系人   | ContactName  | 主要业务对接人    |
| 联系人职务 | ContactTitle | 如采购经理、店长   |
| 所在国家  | Country      | 客户注册地国家    |
| 所在城市  | City         | 客户注册地城市    |
| 联系电话  | Phone        | 座机，含区号     |

### 第六条 客户区域划分

按 `Country` 字段归入四个大区，用于区域分析：

- **华东区**：包含 UK、Germany、France、Sweden、Spain、Italy、Austria、Belgium、Denmark、Finland、Ireland、Norway、Poland、Portugal、Switzerland
- **北美区**：包含 USA、Canada、Mexico
- **南美区**：包含 Brazil、Argentina、Venezuela
- **亚太区**：包含 Japan、Singapore

> 注意：本系统的"区域"是业务划分，与客户表中的 City 无直接对应关系，不得用 City 字段代替区域。

## 第三章 订单表（Orders）

### 第七条 表用途

记录每一笔订单的下单与履约信息，是交易分析的主表。一张订单可包含多个商品明细。

### 第八条 主要字段

| 中文名称   | 字段名          | 说明              |
| ------ | ------------ | --------------- |
| 订单编号   | OrderID      | 主键              |
| 客户编号   | CustomerID   | 关联客户表           |
| 业务员编号  | EmployeeID   | 关联员工表           |
| 下单日期   | OrderDate    | 客户提交订单的日期       |
| 要求到货日期 | RequiredDate | 客户期望收货的最晚日期     |
| 实际发货日期 | ShippedDate  | 仓库实际出库日期，未发货则为空 |
| 承运商编号  | ShipVia      | 关联承运商表          |
| 运费     | Freight      | 本单运费金额          |
| 收货国家   | ShipCountry  | 实际收货地国家         |
| 收货城市   | ShipCity     | 实际收货地城市         |

### 第九条 订单状态判定

系统不设独立的"状态"字段，状态由日期字段推导：

- **未发货**：`ShippedDate` 为空
- **已发货**：`ShippedDate` 不为空
- **逾期发货**：`ShippedDate` 晚于 `RequiredDate`
- **按期发货**：`ShippedDate` 早于或等于 `RequiredDate`

### 第十条 发货提前量

"发货提前量"指要求到货日期与实际发货日期之间的天数差，计算方式为 `RequiredDate - ShippedDate`，单位为天。该值为负表示逾期。

### 第十一条 运费口径

运费 `Freight` 为该订单整单运费，不按商品明细分摊。若需按商品分析运费，须在报表中注明"整单口径"。

## 第四章 订单明细表（Order Details）

### 第十二条 表用途

记录订单中每个商品的成交信息，是销售额计算的唯一依据。

### 第十三条 主要字段

| 中文名称 | 字段名       | 说明                        |
| ---- | --------- | ------------------------- |
| 订单编号 | OrderID   | 与订单表联合主键                  |
| 商品编号 | ProductID | 与商品表联合主键                  |
| 成交单价 | UnitPrice | 下单时的实际单价，不等于商品标准单价        |
| 数量   | Quantity  | 购买件数                      |
| 折扣率  | Discount  | 0 到 0.25 之间的小数，0.1 表示 9 折 |

### 第十四条 销售额计算口径（重要）

单条明细的销售额计算方式为：

```
销售额 = UnitPrice × Quantity × (1 - Discount)
```

**必须使用 `UnitPrice`（成交单价），不得使用商品表中的 `UnitPrice`（标准单价）。** 两者在下单后可能因调价而不一致，用错会导致历史订单金额失真。

### 第十五条 折扣率含义

`Discount` 为让利比例：`0` 表示无折扣（原价），`0.05` 表示 95 折，`0.1` 表示 9 折，`0.25` 表示 75 折，为系统允许的最大折扣。折扣率为空时按 0 处理。

### 第十六条 客单价口径

客单价 = 统计期内总销售额 ÷ 统计期内去重订单数。分母必须是订单数，不是明细行数。

## 第五章 商品表（Products）

### 第十七条 表用途

记录在售与停售商品的基础信息及库存状态。

### 第十八条 主要字段

| 中文名称  | 字段名             | 说明                     |
| ----- | --------------- | ---------------------- |
| 商品编号  | ProductID       | 主键                     |
| 商品名称  | ProductName     | 商品全称                   |
| 供应商编号 | SupplierID      | 关联供应商表                 |
| 分类编号  | CategoryID      | 关联商品分类表                |
| 包装规格  | QuantityPerUnit | 如 "10 boxes x 20 bags" |
| 标准单价  | UnitPrice       | 目录价，非成交价               |
| 库存数量  | UnitsInStock    | 当前可用库存                 |
| 在途数量  | UnitsOnOrder    | 已下单未到货数量               |
| 再订货点  | ReorderLevel    | 触发补货的库存阈值              |
| 是否停售  | Discontinued    | 1 表示已停售，0 表示在售         |

### 第十九条 在售商品

"在售商品"指 `Discontinued = 0` 的商品。任何库存、销量分析若未特别说明，均默认只统计在售商品。

### 第二十条 标准单价与成交单价

商品表的 `UnitPrice` 是目录标准价，仅用于定价参考；订单明细表的 `UnitPrice` 是实际成交价。计算销售额、客单价、折扣金额时必须使用订单明细的成交单价。

## 第六章 商品分类与供应商

### 第二十一条 商品分类表（Categories）

共 8 个分类：饮料（Beverages）、调味品（Condiments）、糕点糖果（Confections）、乳制品（Dairy Products）、谷物杂粮（Grains/Cereals）、肉禽类（Meat/Poultry）、农产品（Produce）、海鲜水产（Seafood）。

### 第二十二条 供应商表（Suppliers）

记录供货方信息，字段与客户表类似，含公司名称、联系人、所在国家与城市。一个供应商可供应多个商品。

## 第七章 员工与承运商

### 第二十三条 员工表（Employees）

记录业务员信息。"业务员业绩"指该员工名下订单的销售额合计。

### 第二十四条 承运商表（Shippers）

记录三家承运商：Speedy Express（即刻快递）、United Package（联合包裹）、Federal Shipping（联邦货运）。

## 第八章 通用指标口径汇总

### 第二十五条 销售额

`SUM(UnitPrice × Quantity × (1 - Discount))`，取自订单明细表。这是唯一正确的销售额算法。

**常用别名**：营收、成交额、卖了多少钱、营业总额、GMV。

### 第二十六条 订单量

`COUNT(DISTINCT OrderID)`。注意去重，因为一张订单在明细表中可能出现多行。

**常用别名**：单数、成交笔数、订单数。

### 第二十七条 销量

`SUM(Quantity)`，单位为件。销量与销售额是不同指标，不可混用。

**常用别名**：件数、出货量、卖了多少件。

### 第二十八条 毛利率

本系统不含成本数据，**无法计算毛利率、利润、成本**。若被问及，应回答"系统未采集成本数据，无法提供该指标"，不得估算。

### 第二十九条 环比与同比

- 环比：与上一个自然月或上一自然周对比
- 同比：与去年同月对比。**本系统仅有 2025 年单年数据，无法计算同比**，被问及时应明确说明。

### 第三十条 时段定义

- "上个月"指相对于当前日期的上一个自然月
- "本季度"指按自然季度划分（1-3 月、4-6 月、7-9 月、10-12 月）
- "最近 30 天"指含当日在内的滚动 30 天，与自然月不同

## 第九章 禁止事项

### 第三十一条 禁止使用的算法

以下做法在本系统中被明确禁止，凡出现即判定为错误口径：

1. 用商品表标准单价计算销售额
2. 用明细行数代替订单数
3. 用 `SUM(Freight)` 分摊到商品维度
4. 估算本系统未采集的成本、利润数据
5. 用客户城市代替业务区域

### 第三十二条 空值处理

聚合计算时，`Discount` 为空按 0 处理；`ShippedDate` 为空表示未发货，在计算平均发货时长时必须排除，不得计入 0。
